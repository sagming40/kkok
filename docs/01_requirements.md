> 버전: v0.1
> 작성일: 2026-09-16

---

## 1. 프로젝트 개요

### 1.1 한 줄 소개
긴 URL을 짧은 주소로 바꿔주고, 그 링크가 **언제 · 어떤 기기로 · 어디서 들어와** 눌렸는지 대시보드로 보여주는 서비스.

### 1.2 목적
- 취업 이후 **기한 없이** 기술 스택을 하나씩 깊게 익히기 위한 자기계발 프로젝트
- 스택의 각 기술이 "써보려고 억지로"가 아니라 **필요해서** 들어가는 구조를 경험하기
- 최소 기능부터 완성한 뒤 단계별로 기능을 쌓아 올리기

### 1.3 운영 형태
- 개발자 본인 + 초대한 지인만 링크를 생성할 수 있는 **초대제 서비스**
- 짧은 링크를 누르는 방문자는 로그인 없이 이용

## 3. 사용자와 권한

### 3.1 사용자 구분

| 구분 | 설명 | 로그인 |
|---|---|:---:|
| 방문자 | 짧은 링크를 누르는 사람 | 불필요 |
| 대기 회원 (`pending`) | 가입은 했지만 초대 코드를 아직 입력하지 않은 사람 | 필요 |
| 회원 (`member`) | 초대 코드로 승격된 사람. 링크 생성 가능 | 필요 |
| 관리자 (`admin`) | 개발자 본인. 초대 코드 발급 · 회원 관리 | 필요 |

### 3.2 권한표

| 기능 | 방문자 | 대기 회원 | 회원 | 관리자 |
|---|:---:|:---:|:---:|:---:|
| 짧은 링크로 이동 | O | O | O | O |
| 초대 코드 입력 | - | O | - | - |
| 링크 생성 · 관리 · 통계 조회 | - | - | O | O |
| 초대 코드 발급 · 조회 | - | - | - | O |
| 회원 관리 | - | - | - | O |

> **인증(Authentication) vs 인가(Authorization)**
> 인증은 "너 누구야?"(입장권 검사), 인가는 "너 이거 할 수 있어?"(자유이용권 확인).
> 로그인했다고 모든 기능이 열리는 게 아니라, 권한 등급으로 한 번 더 확인한다.

## 4. 기능 요구사항

단계는 개발 순서다. **각 단계가 끝날 때마다 동작하는 결과물**이 나와야 한다.

### 1단계 — 핵심 동작

| ID | 기능 | 상세 |
|---|---|---|
| F-01 | 짧은 링크 생성 | 긴 URL을 입력하면 짧은 코드(예: `aB3xK9`)를 발급한다 |
| F-02 | 리다이렉트 | `/{code}` 접속 시 원래 주소로 **302** 응답으로 이동한다. 없는 코드는 404 |
| F-03 | URL 검증 | http/https만 허용, 형식 검사, 이 서비스 자신의 주소는 단축 금지(무한 이동 방지) |

### 2단계 — 회원 · 권한 · 기록

| ID | 기능 | 상세 |
|---|---|---|
| F-04 | 이메일 회원가입 · 로그인 | 이메일 + 비밀번호로 가입/로그인, JWT 발급 |
| F-05 | GitHub 로그인 | OAuth로 가입/로그인. `user:email` 권한으로 **인증된(verified) 이메일**을 확인 |
| F-06 | 로그인 시도 제한 | 일정 횟수 이상 실패 시 일정 시간 로그인 차단 (Redis) |
| F-07 | 권한 등급 | 가입 직후 `pending`, 링크 생성은 `member` 이상만 가능 |
| F-08 | 초대 코드 입력 | `pending` 회원은 초대 코드 입력 화면으로 안내, 유효한 코드 입력 시 `member`로 승격 |
| F-09 | 초대 코드 발급 · 조회 | 관리자가 1회용 코드를 만료일과 함께 발급, 사용 여부 · 사용자 조회 |
| F-10 | 초대 코드 동시 사용 방지 | 같은 코드를 동시에 입력해도 **한 명만** 성공 |
| F-11 | 내 링크 관리 | 내 링크 목록 조회, 삭제, 비활성화 |
| F-12 | 클릭 기록 | 클릭 시각, 기기 · 브라우저(User-Agent), 유입 경로(Referer) 저장 |
| F-13 | 관리자 비밀번호 초기화 | 메일 발송 기능 전까지, 관리자가 회원 비밀번호를 초기화 |

### 3단계 — 분석 · 성능

| ID | 기능 | 상세 |
|---|---|---|
| F-14 | 통계 대시보드 | 일별 클릭 수, 기기 비율, 유입 경로 순위 차트 |
| F-15 | 리다이렉트 캐싱 | 짧은 코드 → 원래 주소 조회를 Redis에 캐싱 |
| F-16 | 링크 생성 횟수 제한 | 사용자별 일정 시간당 생성 개수 제한 (Redis) |
| F-17 | GitHub 계정 연결 · 해제 | 로그인한 상태에서 GitHub 계정을 직접 연결하거나 해제 |

### 4단계 — 확장 기능

| ID | 기능 | 상세 |
|---|---|---|
| F-18 | 커스텀 주소 | `/minkyu-blog`처럼 코드를 직접 지정 (중복 · 예약어 검사) |
| F-19 | 만료일 | 만료된 링크는 이동하지 않고 안내 페이지 표시 |
| F-20 | 링크 미리보기 | 원래 페이지의 제목 · 대표 이미지를 httpx로 수집해 표시 |
| F-21 | 이메일 인증 | 가입 이메일로 인증 메일 발송 (SMTP 연동) |
| F-22 | 비밀번호 재설정 | 1회용 토큰을 메일로 발송, 만료 처리 |

### 5단계 — 배포

| ID | 항목 | 상세 |
|---|---|---|
| D-01 | CI | GitHub Actions에서 푸시마다 pytest 실행 |
| D-02 | 배포 구성 | Nginx 리버스 프록시 + Uvicorn + Docker Compose |

## 5. 비기능 요구사항

| ID | 항목 | 내용 |
|---|---|---|
| N-01 | 속도 | 리다이렉트는 체감상 즉시. 로컬 기준 목표치를 정하고 **캐싱 전후를 직접 측정**한다 |
| N-02 | 안정성 | 클릭 기록 저장이 실패해도 리다이렉트는 정상 동작해야 한다 |
| N-03 | 비밀번호 | argon2 또는 bcrypt 해시로 저장. 원문 저장 금지 |
| N-04 | 개인정보 | IP 주소 원문은 저장하지 않는다 |
| N-05 | 입력 · 에러 | 모든 입력은 Pydantic으로 검증, 에러 응답 형식을 통일한다 |
| N-06 | 테스트 | 코드 생성, URL 검증, 리다이렉트, 초대 코드 사용은 pytest로 검증한다 |
| N-07 | 실행 환경 | `docker compose up` 한 번으로 앱 · DB · Redis가 모두 실행된다 |
| N-08 | 비동기 통일 | DB, Redis, 외부 요청을 모두 async로 처리한다 |
| N-09 | 토큰 관리 | 토큰은 httpOnly 쿠키로 전달, Access Token 15분 · Refresh Token 2주, Refresh Token은 DB에 해시로 저장 |

## 6. 주요 설계 결정

| 결정 | 이유 |
|---|---|
| 리다이렉트는 **302(임시 이동)** 사용 | 301은 브라우저가 기억해버려 이후 클릭이 서버를 거치지 않으므로 **클릭 수를 셀 수 없다** |
| 로그인은 **자체 이메일 + GitHub**까지만 | 서로 다른 인증 방식 2개를 배우는 것이 같은 방식(소셜) 여러 개보다 학습 효과가 크다 |
| `users`와 `social_accounts` 테이블 분리 | 한 회원이 여러 로그인 수단을 가질 수 있는 구조. 나중에 카카오 · 네이버 추가가 쉽다 |
| `password_hash`는 비어 있을 수 있음 | GitHub로만 가입한 회원은 비밀번호가 없다 |
| 이메일이 같아도 **자동 계정 병합 안 함** | 잘못 병합되면 남의 계정에 접근하는 보안 구멍이 될 수 있다. 연결은 로그인 후 직접 한다 |
| 초대 코드는 **가입 후** 입력 | 가입 방식(이메일/GitHub)과 상관없이 입력 창구가 하나로 통일된다. OAuth 왕복 중 코드를 보관할 필요가 없다 |
| 초대 코드 사용은 **확인 + 사용 처리를 한 번의 업데이트로** | 확인과 처리를 나누면 동시에 두 명이 같은 코드를 쓸 수 있다 (선착순 문제) |
| 처음부터 **async** | 리다이렉트 요청이 동시에 많이 일어나는 서비스라 궁합이 좋다 |
| 이메일 인증 · 비밀번호 재설정은 **4단계로 연기** | 메일 발송 연동이 추가로 필요하고, 초대제라 초기 위험이 낮다 |

## 9. 개발 시 주의사항 메모

- **async 지연 로딩 에러**: 연결된 데이터를 나중에 꺼내면 에러가 난다. 필요한 관계는 조회할 때 `selectinload` 등으로 미리 함께 불러온다. `MissingGreenlet` 에러가 보이면 대부분 이 문제다.
- **GitHub 이메일**: 비공개 이메일 사용자가 많다. 이메일 목록 API로 받아와서 verified 여부를 확인한다.
- **Alembic 초기화**: async 프로젝트는 `alembic init -t async`로 시작한다.
- **외부 서비스 정책**: OAuth 앱 설정 등은 붙이는 시점에 공식 문서를 다시 확인한다.
